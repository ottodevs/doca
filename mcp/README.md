# Doca MCP server

A minimal [Model Context Protocol](https://modelcontextprotocol.io) server that lets an AI agent
read Doca positions on Aqua: wallet balances, per-strategy state, and the honorability invariant
(does the wallet actually hold enough to cover every commitment at once).

Zero new dependencies. It's one file (`server.ts`) using `Bun.serve` + `fetch`, talking raw
JSON-RPC `eth_call` to `RPC_URL`. The four contract calls it needs (`balanceOf`, `rawBalances`,
`remainingFraction`, `feeBpsFor`) all take only static arguments (`address`/`bytes32`), so the ABI
encoding is four 32-byte words after a 4-byte selector. No ABI library required. The selectors
are hardcoded, computed once from the exact signatures in `web/src/lib/doca.ts`.

## Run it

```bash
bun mcp/server.ts
# doca-mcp listening on :8420 -> POST /mcp  (RPC http://127.0.0.1:8545)
```

Env vars (both optional):

| Var | Default | Meaning |
|---|---|---|
| `RPC_URL` | `web/src/deployment.json`'s `rpcUrl` (`http://127.0.0.1:8545`) | Chain RPC to read from |
| `MCP_PORT` | `8420` | Port to listen on |

Contract addresses always come from `web/src/deployment.json`: the same file the web app reads,
regenerated by `contracts/scripts/deploy-for-web.ts`.

## Point an agent at it

Any MCP client (HTTP transport): connect to `http://127.0.0.1:8420/mcp`.

```json
{
  "mcpServers": {
    "doca": { "url": "http://127.0.0.1:8420/mcp", "transport": "http" }
  }
}
```

Any MCP client that speaks Streamable HTTP works the same way: point it at `http://<host>:8420/mcp`.
There's no auth and no session state: every call is a fresh read against `RPC_URL`.

## Tools

### `doca_wallet`
Maker's live WETH/USDC balances (`ERC20.balanceOf`, the same calls `web/src/lib/doca.ts` uses).

```json
{ "maker": "0x70997970C51812dc3A010C7d01b50e0d17dc79C8" }   // optional, defaults to the demo maker
```

### `doca_positions`
Per-strategy state for a list of strategy hashes: WETH aboard (`Aqua.rawBalances`), budget-remaining
fraction (`InventorySkewProvider.remainingFraction`), and current fee surcharge (`feeBpsFor`).

```json
{ "hashes": ["0x8c9e8bbe7562b574872b55e472f6df9548e1e64ed6c14132a53d9ad009a5e995"] }
```

Call with `hashes: []` (or omit it) and the tool explains how to obtain one instead of guessing:
Aqua's `Shipped` event has no `indexed` parameters, so there is no cheap `eth_getLogs` filter by
maker, only a full log scan plus manual decode of a dynamic `bytes` tail, which is indexer-shaped
work this server deliberately doesn't take on. The hash is the return value of
`ship()`/`router.hash(order)` in `web/src/lib/doca.ts`, or shown in the Doca app once a strategy is
live.

### `doca_health`
The invariant check: sum the committed amounts (`rawBalances`) across the given strategies on both
legs and compare each against the maker's actual wallet balances. `honorable: true` means the wallet
holds enough WETH *and* enough USDC to cover every checked commitment at once; health is the worse
leg. On-chain enforcement (the BudgetGuard instruction) remains on the roadmap. Nothing is ever
deposited into Aqua up front.

```json
{ "hashes": ["0x8c9e8bbe7562b574872b55e472f6df9548e1e64ed6c14132a53d9ad009a5e995"] }
```

## Example session

```
$ curl -s localhost:8420/mcp -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18"}}'
{"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{}},
 "serverInfo":{"name":"doca-mcp","version":"0.1.0"},"instructions":"Read-only Doca ..."}}

$ curl -s localhost:8420/mcp -d '{"jsonrpc":"2.0","id":2,"method":"tools/call",
    "params":{"name":"doca_wallet","arguments":{}}}'
# -> { maker, weth: {raw, formatted}, usdc: {raw, formatted}, rpc }

$ curl -s localhost:8420/mcp -d '{"jsonrpc":"2.0","id":3,"method":"tools/call",
    "params":{"name":"doca_health","arguments":{"hashes":["0x8c9e..."]}}}'
# -> { walletWeth, committedWeth, headroomWeth, honorable: true, note }
```

## Why no write tools

`ship`/`dock` need a signature. Handing an agent the maker's private key, even the anvil demo key,
so it can move funds unattended is a custody decision this project isn't making by default: the
person who holds the keys should decide when a promise gets made or revoked, not a model acting on
its own initiative. This server is read-plus-advice: an agent can watch a position, compute whether
it's honorable, and tell a human what to do next. It cannot act on its own.

## Roadmap (not implemented)

- **Authenticated write actions.** `ship`/`dock`/`marketFill` behind an explicit, scoped
  authorization step (e.g. a session token minted by the wallet owner, expiring, capability-limited
  to one strategy) so an agent can act only with standing permission, not standing keys.
- **x402-metered premium data (concept only).** Aqua strategy analytics beyond what's free here
  (historical fee curves, cross-market inventory-skew comparisons, backtested budget presets), sold
  per-call over [x402](https://www.x402.org/) instead of a subscription. Nothing about this is
  built; it's one plausible next step once there's data worth metering, written down so it's a
  decision made in the open rather than a surprise later.
